# 验收、报告与桌面包

## 四项独立检查

在project-state每页的checks中分别记录 `layout / copy / product / technical` 的实际状态、证据文件和问题。`pass`必须是本次版本的观察；不能因脚本返回0自动写视觉pass。

|检查|真正要看的东西|不构成通过的证据|
|---|---|---|
|布局|逐页同宽参考/结果，标题字形/行位、商品占比、裁切、叠放、技巧与装饰；完整详情节奏和接缝|只看首屏、文件齐、颜色像、缩略网格、相似度总分|
|文案|逐对象原文/最终文本差异，必要改动依据；原生文字实际渲染、断行、字距、缺字|只检查无溢出或模型没有错字|
|商品|每张生成图与同角度实拍、高风险局部、佩戴接触；每色SKU的实物对应|通用“Product Lock”、同一句批量检查、好看、AI说明|
|技术|实际尺寸、JPG/PSD配对、重开改字换图、嵌入、蒙版、报告和版本|文件能保存、有一个文字层、复制哈希相同|

允许布局通过但商品失败，也允许可编辑通过但设计未通过；这些状态不得合并成一个总分。关键商品结构/配色/穿戴错误、漏参考、未实现的核心技巧、未知必填参数必须明确列出。

文案通过须覆盖所有语言及相联图标；尺寸正确须同时核对图示对象/端点，见[文字联合复审](typography-copy.md)。保留旧版技术证据时注明日期和版本，本轮未重开不得写成本轮已验证。布局加项目组件才是完整制作源：核对layers证据的build_sources和实际组件哈希，确认本次编译带入最终补画；旧证据无该字段时记未追溯，不据此自动否定旧图。

## 审阅包

国内商品图的copy检查还需完成[国内制作审查](commerce-compliance.md)：audit_copy的commerce_findings逐项解决，实际字体留免费商用许可记录，目标平台及跨平台残留看图核对。无关键词命中不代表合规通过；抠图里的文字/Logo/二维码也不能漏查。复用图标的提取质量与其功能语义分别验收。

运行 `project_tools.py check <项目> --stage review` 检查记录完整性；失败先看具体问题，能修复的自行修复。即使有局部blocked，也可 `report` 输出完整可视待审包，页面上直接列出缺失/失败项，不只交第一张样例或空清单。

`report`提供逐页并排、等比叠加和文件入口；本身不代替完整详情长版。另附完整参考/结果长版、手机可读段、关键局部及接缝证据。对照图不可出现在正式可上架目录。实际打开HTML检查图片与相对链接。任何效果判断需看实际结果，不能只读记录。

反馈按页ID/对象位置整理，同类问题检查其他受影响页。按用户明确的审阅方式进行；用户说等发完就等待，不抢跑。常规修复不反复求批准。每次实质改动增加版本，撤销对应页旧批准，并同步分屏/整页/报告。

用户接受“人工简单改改”时，user_approval记 `manual_handoff`，列明人工待改对象与PSD位置；不能把它改写为商品真实通过或上架批准。整套认可也不自动核实尚未知的参数。

## 正式交付

`project_tools.py check <项目> --stage delivery`通过只表示记录与文件符合交付条件；还须本次用户明确批准相同版本。用户未回复不是批准。批准前可以按用户要求给桌面测试包，标题和清单标待验收。

正式商品包按[精简交付](delivery-handoff.md)组织：上架图片、做图源文件、独立模特与场景、许可字体和一份完整报告；不交制作记录与对比、上架清单和单独使用说明。完整内部检查仍在交付前完成，复制校验与PS重开不可省略。

技能安装包与商品文件分开。本技能更新不授权删除历史项目；用户要求清理时先列范围、保留源图/手改/共享资产，复制核验和依赖检查完成后仅处理已授权的任务临时物。不把旧某次授权当永久清理许可。交付不自动发布到商家后台。


## R5.4增量

R5.4验收补充：新增人物、商品、佩戴比例、文案、排版、色款分项观察，用户采用独立记录；整体、商品局部和约200px缩略图都要看。共用PSD必须逐色切换、重开导出并验证测试副本改字换图，准确披露未拆区域。过程对比只供内部制作，不出现在精简商品交付中；最终目录、报告及清理以delivery-handoff.md为准。
